# Generating `debian/upstream.md`

`debian/upstream.md` records, inside each ARCoS package repository, which
upstream the fork tracks and how that was proven. It is rendered from the same
verified resolution the dashboard and the workbook show, so the committed
record and the tool cannot disagree.

Generating writes files **locally** under `out/`. It pushes nothing, creates no
branch, opens no pull request and needs no GitHub token. Proposing the files is
a separate step: [upstream-md-publishing.md](upstream-md-publishing.md).

## Generate for a release

```bash
docker compose exec app apm generate-upstream-md --release bookworm --branch aminor
```

| Option | Meaning |
|---|---|
| `--release` | Debian release (default `bookworm`) |
| `--branch` | Only packages whose ARCoS branch is this (`aminor` for Bookworm). Others are listed as left out; a package is never re-targeted onto a branch its release does not ship |
| `--package` | Only this package; repeatable. **Rewrites the plan with only these packages** - see below |
| `--include-needs-review` | Also write files for `NEEDS_REVIEW` packages (they record the status and the reason, never an invented upstream). They are still never published |
| `--offline` | Do not read the existing file from each fork; every outcome then reads `CREATED`, which is a guess |
| `--out-dir` | Output directory (default `out/`) |

It needs a mapping first (`apm resolve-release --release bookworm`).

### What it writes

| File | Contents |
|---|---|
| `out/upstream-md/<package>/debian/upstream.md` | The file, exactly as it would be committed |
| `out/upstream-md-plan-<release>.json` | The plan: per package the ARCoS repository, base branch, new branch, commit message, outcome, diff, the file's **SHA-256** and size; plus the skipped packages and why. `"pushed": false`, `"pull_requests_created": false` |
| `out/upstream-md-plan-<release>.md` | The same plan as a readable table |

The publisher commits only a file whose bytes still match the plan's SHA-256,
so **the plan is what you review**.

> **Caution:** `--package` writes a plan containing only those packages,
> replacing the full plan. Before publishing several packages (`--all`), run
> the command without `--package` so the plan lists all of them again.

### Which packages get a file

| Status | File? |
|---|---|
| `VERIFIED` | Yes |
| `NEEDS_REVIEW` | Only with `--include-needs-review` (and never published) |
| `NO_UPSTREAM` | No - a file recording an upstream would be fiction |
| `FAILED` | No |

### Outcomes

Before writing, the file already in each fork (at the pinned commit) is read,
read-only, and compared:

| Outcome | Meaning |
|---|---|
| `CREATED` | The fork has no `debian/upstream.md` |
| `UPDATED` | The fork has one this tool wrote, and it has changed |
| `NO_CHANGE` | Identical to what is already committed (ignoring trailing whitespace and line endings) |
| `CONFLICT` | A file this tool did not write - it is never replaced silently |

A fork that could not be read is listed separately: its outcome is what
*would* happen if no file is there, which is not the same as knowing none is.
"Written by this tool" means the file carries the marker line
`<!-- Generated by the ARCoS Package Manager. ... -->`.

## What the file contains

Every line is a field of the resolution; an unknown value is written `N/A`,
never filled with a plausible guess. Generation is deterministic - no
timestamps, no local paths - so it can be compared byte for byte.

| Section | Contents |
|---|---|
| Package | The package name |
| ARCoS | Repository, release, branch, path in the manifest, pinned commit |
| Debian | Release, source package, version, packaging VCS repository and branch |
| Upstream | Repository, branch, tag, commit, commit date, origin kind |
| Release reference | Debian upstream version, target series, base tag (and whether ARCoS contains it), the ref compared against and why, whether it is a fallback |
| Resolution | Mode, status, method, confidence, category, verification level, review reasons; a curated entry and any curated conflict |
| Evidence | Source, URL, verification, common ancestor (and all merge bases), raw commit counts with their basis |
| Content match | Only for forks without shared history: method, closest tag, score, files and lines differing, who approved it |
| Backlog | **Only when a comparison exists for exactly these two commits**: relevant, already present, missing, unknown, reverted, critical/security missing, stable-nominated missing, backport detection |
| Debian patches | Patch counts by kind, CVEs referenced, security patches |
| Warnings | Plausibility warnings |
| Evidence trail | Every evidence line behind the answer |

To include the Backlog section, run `apm compare --package <p>` **before**
generating. Running a comparison *after* generating can change what the
mapping renders; the publisher then reports `DRIFT` and the file must be
generated (and reviewed) again.

## Review checklist

Open `out/upstream-md-plan-<release>.md` and, per package,
`out/upstream-md/<package>/debian/upstream.md`:

- ARCoS repository and branch are the package's fork and release branch
  (e.g. `Arrcus/mstpd`, `aminor`).
- Upstream repository and branch/tag are the project you expect, and
  `Fallback ref: no` (or you accept the fallback).
- `Status: VERIFIED`, `Verification level: SHARED_HISTORY` (or
  `CONTENT_MATCH_APPROVED` with a named approver).
- No warning you cannot explain.
- Outcome `CREATED` or `UPDATED`. `CONFLICT` needs a person to compare the
  existing file first; `NO_CHANGE` needs nothing.

Check that the files still match the mapping and the plan:

```bash
docker compose exec app python scripts/verify_upstream_md.py bookworm
```

## One package, from the dashboard or the API

The dashboard's **debian/upstream.md** card - **Generate** - renders the file
for the selected package and shows the diff against the fork and the outcome
badge. It does not write the plan.

```bash
curl -s -X POST http://<server-ip>:8080/api/upstream-md/generate \
  -H 'Content-Type: application/json' \
  -d '{"package": "mstpd", "release": "bookworm"}'
```

Returns the content, the outcome and the diff. `"write_local": true` also saves
it as `out/upstream-md/<package>__<release>.md`. A `NO_UPSTREAM` package is
refused (HTTP 400).
