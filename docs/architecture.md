# Architecture

## Layers

```
frontend/  React + TypeScript + Vite
    │  fetch, types generated from the OpenAPI schema
    ▼
src/apm/api/        FastAPI. Routes validate and delegate. No git, no rules.
src/apm/services/   All behaviour lives here.
src/apm/domain/     The vocabulary: entities and enums, shared by everything.
src/apm/gitio/      Where git runs, and the workspaces it runs in.
src/apm/debian/     Debian archive metadata.
src/apm/upstream/   Candidate discovery and URL normalisation.
```

The CLI, the API and the report writer all build the same object graph from
`services/container.py`, so there is no second place where behaviour is wired up
slightly differently.

## One mapping, several renderings

There is exactly one resolution per (package, release). Everything else is a
view of it:

```
Resolver.resolve_one()  ->  Resolution
      │
      ├─ report.to_row()          -> out/upstream-mapping.{csv,xlsx}    (canonical, all releases)
      ├─ report.release_row()     -> out/upstream-mapping-<release>.{csv,xlsx}
      ├─ MappingStore             -> the API, and so the dashboard
      └─ UpstreamMdService        -> debian/upstream.md
```

The workbook, the dashboard and the committed `debian/upstream.md` cannot
disagree, because none of them holds its own copy of the mapping. A second
hand-maintained mapping is the thing this structure exists to prevent.

`services/metadata_batch_service.py` drives the last of those across a whole
release and writes the branch/commit plan beside the files. It reads each fork
to compare, and that is the only remote effect it has: it never writes.

## Why the layers are separated this way

**Routes contain no logic.** Every route resolves dependencies, calls one service
and returns a domain model. This is what lets the CLI and the API produce
identical answers: they call the same service.

**The domain model is the contract.** Responses are the domain objects
themselves, and `scripts/generate_frontend_types.py` emits TypeScript from the
schema FastAPI serves. A field added to a model reaches the frontend's types on
the next regeneration; a mismatch is a compile error rather than an `undefined`.

**Git access is a transport, not a dependency.** The machine running this tool
may not be the machine with repository access. `gitio/transport.py` turns that
into one decision — does this URL need the bridge? — made from configuration.
Nothing above that layer knows a host name.

## Request paths

Resolving an upstream:

```
GET /api/upstream/{package}
  → UpstreamService.resolve
      → Resolver (the verified mapping pipeline, unchanged)
          → SourcesIndex     Debian metadata
          → strategies       curated → kernel → DEP-12 → watch → homepage
          → AncestryChecker  merge-base against each candidate
      → adapters.to_domain_resolution
```

Comparing:

```
POST /api/comparison
  → UpstreamService.resolve       (or resolve_manual)
  → ComparisonService.compare
      → WorkspaceManager.for_package   a real repo, on the git host
      → fetch both sides, merge-base
      → PatchIdService.compare         backport detection
      → CriticalityService.assess      per commit, from evidence
```

Applying:

```
POST /api/patches/preview       throwaway workspace, destroyed after
POST /api/patches/cherry-pick   new branch, never the target branch
POST /api/pull-requests         explicit, separate call
```

## Where state lives

Nothing is stored in a database. The durable artefacts are:

| What | Where |
|---|---|
| Package catalogue | `config/packages.yaml`, generated by `apm discover` |
| Curated mappings | `config/overrides.yaml`, hand-written |
| Debian indices, pool tarballs | `$APM_CACHE_DIR/http` |
| Ancestry probe results | `$APM_CACHE_DIR/ancestry` |
| Git workspaces | `$APM_WORKSPACE_DIR`, on the git host |
| Mapping report | `out/upstream-mapping.{csv,xlsx}` |

Resolutions are cached in memory for 15 minutes; comparisons are recomputed, but
the workspace is reused, which takes a repeat comparison from minutes to seconds.
